## (5) OpenAdapt 等「操作記録→自動化／文書化」の評判

| 項目 | 内容 |
|------|------|
| **OpenAdaptとは** | OSS。GUIデモを記録し、LMM/VLMと繋いで**Demonstrate → Learn → Execute**。公式は「Generative Process Automation / 自己修復デスクトップ自動化」。**主目的は文書化ではなく再実行（RPA）**。 |
| **X上の評判** | 2025–26は**創業者発信・GitHub紹介・UI-TARS等エージェント文脈での名前出し**が中心。Scribe級のバイラルリストには乗らない。2026-04に第三者AIレビュー風投稿（★3.7/5）あり。**熱狂的ユーザー大量レビューは観測されず**。 |
| **強みとして語られる点** | デモに制約した行動でアライメント、ローカル／デプロイ手順の公開、エージェント研究のベース。 |
| **弱み・空白** | 「きれいなSOP/Markdownを出す製品」としての認知は薄い。セットアップ難易度・完成度の**一般ユーザー向け評判は未成熟**（SourceForgeレビュー枠もほぼ空）。 |
| **近縁カテゴリ** | UI-TARS、AskUI、Computer Use系、Codex Record&Replay——**「見せた操作をエージェントが再利用」**が2026の本流。文書化は副産物扱い。 |

## 我々のツール（screen-activity-logger）の立ち位置・3行

1. **競合マップ**: Scribe/Tango/Guiddeは「操作中キャプチャ→クラウドSOP」、Teachme/tebikiは「現場動画マニュアルSaaS」、NotebookLM系は「学習用要約」、OpenAdaptは「記録→再実行」——いずれも**既存の任意MP4を完全ローカルでOCR+VLM+ASRし、タイムスタンプ付き作業ログにする**レイヤはほぼ空白。  
2. **差別化**: クラウド非依存・日本語OCR密＋VLM疎の二層・ASR併用で「文字・状況・発話」を統合し、**手順書SaaSではなく監査・振り返り・RAG向けの生ログ**を出す点。  
3. **勝ち筋**: エンタープライズの機密画面／個人のローカル運用／バグ再現ログ（Heimdall近縁）で「SaaSに上げられない動画」を処理する**インフラ層**として立ち、SOP美観はScribe系・実行はOpenAdapt系に譲るポジションが自然。
